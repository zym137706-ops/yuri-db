## 0. 为什么去重是这个项目的核心难点

同一个作品会在多个源里以**不同形态**出现：

| 源 | 它"看到"的作品 |
|---|---|
| NDL 全国書誌 | 每一**册**一条记录（第1巻、第2巻…），标题带卷次 |
| openBD | 每一**册**一条记录，有 `series`（レーベル名）但不一定有系列 ID |
| カドコミ | 一个 **series** 一条记录（`KC_000232_S`），带 8,151 部 |
| コミック百合姫 官网 | 连载**作品**（无 ISBN） |
| 東立 | 每一**册**一条记录，**含「原文書名」** |
| cppinfo | 每一**册**一条记录 |
| AniList | 一个**动画**条目 |

所以「一件事」在物理上有三种粒度：**册（Volume）→ 系列（Work）→ 动画（Anime）**。
本项目的去重必须先把粒度对齐，再去重。`schema.prisma` 里 `Work` / `Volume` / `Anime`
的三层就是这个原因。

## 1. 三级键：从最强到最弱

### L1 — ISBN-13（决定性，最强）

ISBN 是**唯一稳定的跨源连接键**。只要两册的 ISBN 相同，就是同一册。

**归一化规则**：

```
1. 去除连字符、空格、全角字符（NFKC）
2. ISBN-10 → ISBN-13 转换（前缀 978 + 重算校验位）
3. 校验位验证（mod-10）；校验失败 → 丢弃，标记为无效而非修复
4. 统一为 13 位数字字符串
```

> ⚠️ **不要做的事**：不要从「978-4-7580-7835-1」这种**看起来像**的东西推断 ISBN。
> NDL 的 OpenSearch `isbn` 是「10/13 桁互相转换后完全一致；其他位数则前方一致」，
> SRU 的 `isbn` 才是纯完全一致 —— **两个端点的匹配语义不同**，混用会造出假匹配。
> 参见 `sources.yaml` → `ja_ndl_search_sru_opensearch`。

**注意区域**：日版、繁中版、简中版各有**自己的 ISBN**。
所以同一部作品的日版第 1 卷与繁中版第 1 卷 ISBN 不同 —— ISBN 只能用来确定
「哪一册是同一册」，**不能直接用来确定「哪部作品是同一部作品」**。
跨语言关联要走 L3。

### L2 — 平台稳定 ID

| 源 | ID 形态 | 用途 |
|---|---|---|
| カドコミ | `KC_000232_S` | 8,151 部 series 的一等键 |
| なろう | `Nコード`（如 `N1234AB`） | Web 小说 |
| カクヨム | 作品 ID | Web 小说 |
| しょぼいカレンダー | `TID` | 动画放送 |
| AniList | `Media.id` | 动画 |

落在 `ExternalId` 表，唯一约束 `@@unique([sourceId, externalId])`。
**这是最可靠的去重手段**，应优先建立：先用 sitemap 把 `KC_*` / `Nコード` 全量灌进
`ExternalId`，再让其他源往上挂。

### L3 — 归一化指纹（模糊匹配，用于跨语言与无 ISBN 场景）

**标题归一化 `titleKey`**：

```
1. Unicode NFKC（全角→半角、兼容字符统一）
2. 统一波浪线/破折号：〜 ～ ~ → ~ ；－ − — – → -
3. 去除所有空白（含 U+3000 全角空格）
4. 去除卷次后缀：
   （N） (N) 【N】 [N] 第N巻 第N卷 N巻 巻之N  #N  N(末尾独立数字)
   ⚠️ 但 "1" 这种纯数字标题要保护（例：《1》）
5. 去除常见装饰后缀： ～...～ 系列名
6. 拉丁字母 → 小写
7. 片假名长音符保留（它区分词义）
```

> ⚠️ **不要把片假名转成平假名、也不要罗马字化**作为匹配键。
> 「ゆるゆり」与「ゆるゆり♪♪」是不同作品；「citrus」与「citrus+」是**不同的系列**。
> 过度归一化会把续作合并进本篇 —— 这是本项目最容易犯的严重错误。

**作者归一化 `nameKey`**：

```
1. NFKC
2. 去除所有空白（"仲谷 鳰" → "仲谷鳰"）
3. 去除中黒「・」两侧空白
4. 去除敬称（先生/氏）
5. 拉丁字母小写
```

**出版社归一化 `nameKey`**：

```
1. NFKC
2. 去除法人格：株式会社 / (株) / 有限会社 / Inc. / LLC / 合同会社
3. 统一异体：台灣角川/台湾角川 → 台湾角川 ；講談社/讲谈社 → 讲谈社
4. 去除尾部「出版」「出版社」「書店」以外的修饰词仅在有歧义时处理
   ⚠️ 不可把「白泉社」和「白泉社出版」当成不同（但也不要把「小学館」与「小学館集英社プロダクション」合并）
```

## 2. 候选生成（Blocking）—— 避免 O(n²)

全库 n 部作品两两比较是 n² 次。1,000 部 = 50 万次，10,000 部 = 5,000 万次。
必须先用**分块键**把候选压到同一桶里：

| 优先级 | 分块键 | 说明 |
|---|---|---|
| B1 | `isbn13` | 精确命中，直接判定同一册 |
| B2 | `externalId` | 平台 ID 精确命中 |
| B3 | `titleKey[0:4]` | 标题前 4 字符（含日文假名/汉字） |
| B4 | `nameKey`（第一作者） | 作者桶 |
| B5 | `publisherKey + volumeNumber` | 出版社+卷次桶 |

**只有落在同一桶内的记录才进入打分**。B3 用前 4 字符而不是首字母：日文标题首字
信息量低（「私」「私の」「私だって」会撞桶），4 字符能显著降噪同时保持召回。

## 3. 打分与阈值

在同一桶内两两打分：

```
score = 0.45 * titleSim        (归一化标题相似度，0..1)
      + 0.25 * authorSim       (作者集合 Jaccard / 1 若第一作者 nameKey 相同)
      + 0.15 * publisherSim    (出版社相同=1，同集团=0.6)
      + 0.15 * metadataSim     (media_type 相同=1，date 相差 <90 天=1，卷数接近…)

硬性否决（无论分数多高，直接判定不同作品）：
  V1. media_type 不同               （漫画 ≠ 轻小说）
  V2. 第一作者 nameKey 都非空且不同  （同名不同作者）
  V3. 两者都有 ISBN 且不同           （是不同册）
  V4. 分属不同区域且标题语言不同      （见 §4，走 L3 跨语言流程而非合并）
```

**阈值**：

| 分数 | 动作 |
|---|---|
| ≥ 0.92 | **自动合并**，写入 `ChangeLog(change_type=updated)` 并记录被合并 id |
| 0.75 – 0.92 | 进入**人工复核队列**（`data/review_queue.json`），不自动合并 |
| < 0.75 | 判定为不同作品 |

> **保守优先**：宁可留下重复条目，也不要错误合并。错误合并会把两个作品的卷、
> 评分、动画信息混在一起，且**很难被发现**；重复条目则肉眼可见、随时可修。
> 因此自动合并阈值定在 0.92（偏高），并且**永不自动跨 media_type / 跨语言合并**。

## 4. 跨语言关联（日版 ↔ 繁中 ↔ 简中）

这**不是去重**，是**关联**：它们是同一部作品的不同语言版本，应挂在同一个 `Work` 下，
用 `Volume.region` 区分。这也是本项目选择「Work 为系列、Volume 带 region」的原因。

**最可靠的关联路径（实测可用）**：

| 路径 | 强度 | 说明 |
|---|---|---|
| **東立 `BooksDetail` 的「原文書名」** | ★★★ | 直接给出日文原名，是**最强的跨语言锚点**。例：`魔入りました!入間くん if Episode of 魔フィア` |
| **NCL ISBN 的「叢書名」+ 譯者** | ★★ | 国家级权威，覆盖未上市新书 |
| **豆瓣 `works/{id}`「全部版本(N)」** | ★★ | 版本对映极准，但**只能人工**（条款禁止爬取） |
| **cppinfo ISBN 直链** | ★★ | 简中侧权威 |
| 标题机器翻译 | ☆ | **不要用**。会造出假关联 |

**关联判定**：`原文書名`（归一化后）== 日版 `titleJa`（归一化后）→ 挂到同一 Work。
仅标题相似**不足以**关联，必须有 ISBN 或原文书名或官方序列表佐证。

## 5. 已知的高危陷阱（必须写进测试用例）

| # | 陷阱 | 例 | 处置 |
|---|---|---|---|
| T1 | **续作 vs 本篇** | `citrus` / `citrus+`；`ゆるゆり` / `ゆるゆり♪♪` | 归一化**不**去除 `+` `♪♪` `S` `2` 等续作标记 → 判为不同 Work，用 `Series` 关联（见 §7） |
| T2 | **同名不同作者** | 多个「百合アンソロジー」 | V2 硬性否决；`編集` 作为作者参与比较 |
| T3 | **アンソロジー** | 「コミック百合姫」系 anthology | **一律不自动合并**，且 `Work` 需 `isAnthology` 标记（建议阶段 4 加） |
| T4 | **卷次在标题里** | 「終將成為妳 (1)」vs「やがて君になる 1」 | 归一化去卷次后比较；卷次进 `Volume.volumeNumber` |
| T5 | **书店标题含促销词** | 「【特装版】…」「限定版」 | 归一化去除 `【…】` 装饰块，但保留「特装版」到 `Volume.edition` |
| T6 | **繁简/异体字** | 「台灣角川 / 台湾角川」「終將成為妳 / 终将成为你」 | 出版社走 `nameKey` 异体表；**标题不跨简繁归一**（属跨语言，走 §4） |
| T7 | **自主制作志** | ガレット（GALETTE WORKS，非大社） | 不要把 publisher 误填为大型出版社；`Publisher.country`/自立项区分 |
| T8 | **已休刊杂志** | つぼみ、きららミラク、コミック百合姫S | `SerializationOutlet.isActive=false` + `endedAt`，不得与现役同名项合并 |
| T9 | **ISBN 重复印次** | 同 ISBN 重版 | 同 ISBN = 同册，重版信息进 `RawFetch`/`ChangeLog`，不新建 Volume |
| T10 | **电子版 vs 纸版** | 同作品 EPUB 与纸质 | `Volume.format` 区分，**不合并**（繁中电子与纸质上架进度常不同步） |

## 6. 合并语义（Merge）

**执行顺序**：

```
1. 选定 survivor：字段非空数最多 → 其次 createdAt 最早 → 其次 id 字典序
2. 字段级合并：
   对每个字段，取 confidence 最高者；
   置信度相同时，survivor 优先（稳定性）
   ⚠️ 绝不用低置信值覆盖高置信值
   冲突无法判定 → 记入 review_queue，字段保持 survivor 原值
3. 关系重挂：ExternalId / Volume / Citation / RatingSnapshot /
             ReviewMeta / Anime / WorkGenre / WorkContributor → 指向 survivor
4. 冲突去重：Volume 按 (region, format, volumeNumber) 唯一；重复者择信息更全的一条
5. 记录：ChangeLog(change_type=updated, entityType=work,
                   oldValue=loser.id, newValue=survivor.id, note=merge)
6. 软删除 loser：Work.mergedIntoId = survivor.id（不物理删除，支持 unmerge）
```

**Unmerge**：因为 loser 只是被标记而非删除，且 `ChangeLog` 保留了完整的合并记录，
可以从 `ChangeLog` 反向重建。**这是必须保留的能力** —— 合并错误只有在人工看到
成品页面时才会暴露。

## 9. 工程实现建议

- **语言**：Python（`collectors/` 已是 Python），依赖 `rapidfuzz`（比 difflib 快且准）
- **不需要**：dedupe / recordlinkage 这类重库；规则明确时自己写更可控
- **运行**：去重作为独立阶段（`scripts/dedupe.py`），在采集与标准化之后、入库之前
- **可观测**：每次运行输出 `merge_decisions.json`（含分数与依据），供人工复核
- **CI 门禁**：U1–U8 作为单元测试，合并逻辑改动必须过测试
